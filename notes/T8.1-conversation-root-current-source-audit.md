# T8.1：Conversation Root 当前来源审计

**官方基线：** `deepseek-ai/deepseek-harness@528c682e061696f5a160f363f236ecbf53cbd006`（`dsh-v0.1.1-rc.1`）。此记录审计 session header、view slot 与 composer 在 welcome/blank/session 过渡中的 tree ownership；它不将静态源码阅读替代为当前 macOS runtime 验收。

## 锁定官方契约

官方 `ConversationRoot` 明确将 hero chrome、session chain 和 `conversation.composer.bar` 作为 resident skeleton 的组成部分：无 session 与有 session 的转换以 owner props 驱动同一个 session-maybe composer slot 进入 inert、hero 或 docked 状态，而不是交换 composer DOM subtree。[1] 当 blank history 仍在 replay 且 blank/hero 归属尚不可判定时，官方暂时隐藏 composer，避免先渲染 hero 再跳为 docked bar；已由 list summary 证明 blank 的 session 则可直接留在 hero。[1]

`conversation.session.header`、`conversation.session`、composer overlays/left/right items 与 dock 都通过 slot chain 提供扩展点。workspace chip 的 label 按 pending pick、no session、workspace membership、loading cwd fallback 与已删除 workspace 的 placeholder 次序解析，避免 authority refresh 时错误闪烁已删除目录名。[1]

| 契约 | 当前原生状态 | 后续工作 |
|---|---|---|
| session header 与 typed view registry | `NativeConversationHeader`、`NativeConversationViewRegistry`、header contribution registry 已接入 active surface | 继续由独立 macOS XCTest/AX 验证。 |
| blank session agent preset seat | `NativeAgentPresetSeat` 只在完整 Host snapshot 指明 selected blank session 时出现 | 继续验证 session lifecycle 与 visuals。 |
| resident composer across mode transition | `NativeConversationColumn` 目前将 `.welcome` 分派至 `NativeWelcomeSurface`，将 session modes 分派至 `NativeActiveConversationSurface` | **尚未证明与官方单一 resident composer tree 等价；不得将 T8.1 视为完成。** |
| replay settling | native 当前必须以 authoritative history/projection lifecycle 建立等价的 hidden/hero/docked state | 需要生产重构、回归和 macOS visual/interaction evidence。 |

因此，T8.1 的下一项生产工作应在当前 App XCTest 编译链重新变绿后，将 welcome、blank 与 active composer 表示收敛到单一有状态 native conversation root，保持 draft/focus/input identity，不以复制两份 `NativeComposerCard` 的方式伪造无闪烁。该工作必须继续仅使用 `OfficialUISpec` 已登记的文本、token 与 geometry，且以当前官方状态机为依据。
