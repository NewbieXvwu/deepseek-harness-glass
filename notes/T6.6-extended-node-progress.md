## 已完成子块：durable inbox 与 steering 分类

官方 [`conversation-nodes/inbox.ts`][1] 把每个 `agent/inbox/spliced` durable event 作为 state-only context：`next-turn` 与 `next-step` 各自累计 pending identity；对于未取消的 next-step splice，被移除的 ID 进入 claimed 集合。随后 [`conversation-nodes/message.ts`][2] 只在 `user/message` 为 append surface、source kind 为 user 且该 message ID 已被 next-step claimed 时，将该消息 materialize 为 `steering`；否则它是普通 `user`，非 user source 则保持 `context`。

本地 `InboxDefinition` 以两个 Core-only state-only definition（`inbox-next-turn`、`inbox-next-step`）映射此语义，读取 `target`、`start`、`removedCount`、`inserted` 与 `outcome`，并通过 `ConversationContextReader.previous` 维护先前 durable inbox state。`InputMessageDefinition` 不再基于 UI 时间或 queue snapshot 猜测 steering，而是只消费该前置 Core state；`CoreUserMessageNode.Kind` 和 materialized chat target 现在明确包含 `steering`。

`testDurableNextStepInboxSpliceClassifiesOnlyClaimedUserMessageAsSteering` 构造一个完整的 next-step admission：先插入 `steer-me`，再用未取消 splice 移除，再 append 两个 user messages。断言被 Host 认领的第一条为 `steering`，未认领的第二条仍为 `user`，并且 inbox contexts 不生成虚假的 timeline/chat row。

## 进行中子块：goal whole-value projection

官方 [`goals.schema.ts`][3] 明确指出 mutation 只返回 `{ ref }` acknowledgement，当前状态**只**经 session projection key `goal` 传输。官方 [`goal/types.ts`][4] 将它定义为完整 `GoalProjection | null`：current durable `goal`（id、revision、objective、phase、blockedReason、maxGoalRounds）加 roundsStarted/createdAt/updatedAt；`null` 是 create 前或 clear 后 tombstone，whole-value last-wins 的折叠由 Host/runtime projection 层完成。

本子块待其自身的 macOS-26 CI 通过后才可标为已验证；它不等同于 T6.6 完成，也不替代 goal 的实际 native renderer/交互、todo/queue 或其余扩展节点。

## 下一子块规格：jobs presentation

官方 `JobListAction.tsx` 规定：无 jobs 时 header control 不渲染；running/stopping 为 live；live jobs 先按 startedAt 升序，settled jobs 再按 finishedAt（回退 startedAt）降序；状态颜色语义为 running=ongoing、stopping/killed=warning、completed=done、failed=error；live duration 仅在展开面板时按秒刷新。既有 `NativeSessionStore.BackgroundJob` 已保留稳定 id/kind/label/status/detail/start/finish 与 `isLive`，下一实现将把该 Host whole snapshot 接入同等的原生 header/panel，而不会重折叠或猜测 job payload。

本地接入审阅：`NativeActiveConversationSurface` 目前以无状态 `NativeConversationHeader()` 作为 transcript 之上的唯一 header；它尚未接收 `NativeSessionStore`，且 UI 目录未发现可复用的 jobs/status popover。jobs presentation 将先把 header 改为显式接收 session store，再以 `BackgroundJob` typed snapshot 实现官方空态隐藏、排序、状态映射、展开态 live duration 和 accessibility，然后补齐官方/原生视觉配对；在此之前不得声称 jobs renderer 完成。
Jobs locale 审阅：锁定 `OfficialLocaleCatalog` 已含 `ui-jobs` count/status/duration 文案，但 `OfficialUISpec.Text` 尚未生成对应 typed Swift 常量。原生 jobs renderer 实施前需先按既有官方 locale 生成/查询路径补齐该受控入口并为 en/zh snapshot 覆盖；不得改用硬编码英文文案。

### feedback 规格结论（研究中）

锁定官方 [`ui-message-feedback/controller.ts`][16] 表明 feedback 不是 `session/event` conversation node：它是每个 Session 一个的 Host-owned durable sidecar。`list` whole snapshot seed 所有 message controls；`put`/`delete` 必须携带最后观察到的 item version；`version-conflict` reply 直接携带 authoritative item 用于 reconciliation；同一 session mutation 串行化，reconnect 使用排在 mutation tail 后的 `resync`，transport/business failure 都以 settled result 返回，不能 optimistic 伪造已保存反馈。下一步须先确认本地 `HarnessAPIs`/DTO manifest 是否有官方 message-feedback typed facade；若 payload 不在固定 rc.7 manifest，必须以 unavailable/read-only renderer 降级并记录，不得私自发明 RPC path。
