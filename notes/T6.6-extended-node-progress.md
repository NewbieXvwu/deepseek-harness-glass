# T6.6：扩展 Conversation Nodes 进度记录

**锁定官方版本：** `deepseek-ai/deepseek-harness@99f6f02fecdb7dff40c3fbc9470f5907c29f74ca`

## 已完成子块：durable inbox 与 steering 分类

官方 [`conversation-nodes/inbox.ts`][1] 把每个 `agent/inbox/spliced` durable event 作为 state-only context：`next-turn` 与 `next-step` 各自累计 pending identity；对于未取消的 next-step splice，被移除的 ID 进入 claimed 集合。随后 [`conversation-nodes/message.ts`][2] 只在 `user/message` 为 append surface、source kind 为 user 且该 message ID 已被 next-step claimed 时，将该消息 materialize 为 `steering`；否则它是普通 `user`，非 user source 则保持 `context`。

本地 `InboxDefinition` 以两个 Core-only state-only definition（`inbox-next-turn`、`inbox-next-step`）映射此语义，读取 `target`、`start`、`removedCount`、`inserted` 与 `outcome`，并通过 `ConversationContextReader.previous` 维护先前 durable inbox state。`InputMessageDefinition` 不再基于 UI 时间或 queue snapshot 猜测 steering，而是只消费该前置 Core state；`CoreUserMessageNode.Kind` 和 materialized chat target 现在明确包含 `steering`。

`testDurableNextStepInboxSpliceClassifiesOnlyClaimedUserMessageAsSteering` 构造一个完整的 next-step admission：先插入 `steer-me`，再用未取消 splice 移除，再 append 两个 user messages。断言被 Host 认领的第一条为 `steering`，未认领的第二条仍为 `user`，并且 inbox contexts 不生成虚假的 timeline/chat row。
