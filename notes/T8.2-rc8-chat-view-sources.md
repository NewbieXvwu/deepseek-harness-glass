## `ab4ebba` / `2aee019` 实现与 macOS-26 验证

初始实现 `ab4ebba` 的 macOS-26 run `32340097848` 在独立 SwiftPM 编译阶段失败：`TranscriptItem` 给新增 `time` 属性提供 stored-property default 后，Swift 不再合成接收 `time:` 的 memberwise initializer。此失败已在 `2aee019` 中用显式、带 `time: Double? = nil` 的 initializer 修复，未采用跳过 Core 事件时间的降级方式。

`2aee019` 的 macOS-26 [run 32340324169](https://github.com/NewbieXvwu/deepseek-harness-glass/actions/runs/32340324169) **success**：规格/架构门禁、独立 SwiftPM 编译、全部 XCTest、app assembly、WindowServer snapshots 与 visual compare 均通过。原生 Jobs 工件确认 user 与 assistant durable row 均出现 native copy action 与 `06:44` Host-event clock，copy/time 不是 UI 侧 optimistic transcript 数据；其 `tailSignature` 仅包含 row id、tail text count 与 running flag，使 streaming text delta 不会重建前序 `LazyVStack` rows。

## `df057b6` 之后：stable chat-node renderer 接入（待 macOS-26 CI）

`NativeSessionStore` 已新增 session-owned `ConversationNodeReducer` 与公开只读 `chatNodes` 快照。完整 `session/history` 通过 reducer `replaceWindow` 重新建立 authority window，older page 通过 `prepend`，`session/event` mux 通过 `append`；resident session 切换保存/恢复原始 event window，而不是保存 UI 重新拼装的 chat 行。`NativeTranscriptScrollView` 现只消费 reducer 的 `target == "chat"` stable keyed nodes；`ToolInvocation` 仍单独保留给 T9.1，未被本次改造成重复工具 renderer。

Jobs 与 tooling snapshot fixture 也已改为注入 Host-shaped user → turn → step → assistant event window，再兼容投影旧 `TranscriptItem` 给尚未迁移的下游表面。`NativeSessionStoreTests.testReducerBackedJobsFixtureMatchesTranscriptAndStreamingFinalReusesSameNodeKey` 将 fixture snapshot 与兼容 transcript 对照，并对真实 mux replay 断言：`assistant/chunk` 后得到 running `CoreAssistantNode`，随后 `assistant/message` 仍使用同一 stable node key 并变为 settled，而非追加第二个 row。这是运行态 reducer snapshot 回归，不依赖 Swift 源码词法匹配。

本次仅让 context 作为 disclosure row 呈现，user/steering 复用 user bubble，assistant 使用 reducer text blocks 与原有 copy/time chrome。reasoning/Markdown/代码/链接、metrics/turn chrome、feedback/branch 以及完整工具 node 仍分别属于 T8.3、T8.2 剩余收敛和 T9；T8.2 **继续未勾选**，必须取得本提交 macOS-26 XCTest、同状态 official/native Jobs 浅/深色配对、差异分类及 enforce 证据后才能闭环。
