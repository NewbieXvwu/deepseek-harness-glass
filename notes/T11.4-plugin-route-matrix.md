# T11.4：插件分流器与兼容矩阵

**状态：** 已实现纯 Core 路由决策与共享 profile 安全过滤，具 Core XCTest、Linux Swift 回归和 `portable-checks` 接入；整体任务仍未完成，
因为 Ghost Plane activation、Host profile discovery 和用户可见 diagnostics 尚未连接到真实 Host。


## 1. 官方运行时依据

锁定官方动态 Cordis runner 以稳定 `pluginId`、不可变 `packageId`、精确 `pluginRunId`、`agentId` 和 package name 标识 browser-half activation。
重复同 run 是 no-op，不同 run 替换；
unload 会删除 loader entry、失效 module factory、清理 styles。缺失 inject services 的 package 是成功但 parked 的 `waitingFor`，而不是可被 silently re-routed 的失败。[1]

因此，`PluginRouteMatrix` 是**不执行** code 的装配前决策层：它不解析 raw manifest、不加载 `/client.js`、不创建 process、不赋予 capability，也不把 display name 当作 identity。
输入只接受已由 `NativeUIManifestVerifier` 得到的 route；后续运行时必须保留 plugin/package/run 三重身份与 official failure stage。

## 2. 固定优先级

| 优先级 | 前提 | 目标 | 安全含义 |
|---|---|---|---|
| 1 | 审阅 registry exact plugin ID、锁定 Host build、verified native manifest | `swiftAdapter` | 只选择 source-controlled native fast path。 |
| 2 | verified native manifest，且 manifest plugin ID 与请求完全相等 | `nativeManifest` | 用闭合 SwiftUI schema form，不解释动态 view。 |
| 3 | 前两者不成立，Ghost Plane 已被上游 host admission | `ghostPlane` | 只是路由候选；实际 module/bridge 注入仍须再通过 GP-2 gate。 |
| 4 | Ghost Plane 不可用或身份错误 | `hostOnly` | 不加载未被承认的 plugin UI。 |

`exclusiveStdio` 和 `tui` 运行时在默认 `.
sharedWeb` profile 被优先拒绝为 `hostOnly(.isolatedProfileRequired)`，即使存在 native adapter 或 manifest。选择 `.isolated(name:)` 后可继续后续 route admission。
这实现“竞争 stdio/TUI 不得加入共享 profile”的保守默认，独立 profile 启动、持久化切换与 UI 提示仍属于 GP-6。

plugin identity mismatch。
