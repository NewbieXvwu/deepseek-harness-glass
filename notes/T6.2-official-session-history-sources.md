# T6.2：SessionHistoryPager 官方来源、行为映射与证据边界

**锁定官方版本：** `deepseek-ai/deepseek-harness@99f6f02fecdb7dff40c3fbc9470f5907c29f74ca`

**原生实现：** `glass/Sources/Core/Session/SessionHistoryPager.swift`

**原生测试：** `glass/Tests/Core/SessionHistoryPagerTests.swift`

## 范围

`SessionHistoryPager` 是 Core 层的 Host-authoritative **原始事件窗口**。它不解析业务节点、不渲染 SwiftUI、也不拥有任何 AppKit/WebKit 表面；其输出仅是连续的 `SessionHistoryEntryDTO` 区间、对应 projection baseline、`hasMore` 与显式加载/错误状态。`ConversationNodeReducer` 和后续 Chat renderer 消费该窗口，因此本任务的视觉证据采用**Core-only 边界审阅**，而不伪造一个尚未由 T8.2 完成的分页界面。

> 这不是对分页视觉的豁免。待 T8.2 `ChatView` 呈现历史分页后，相关用户可见状态必须以相同官方 fixture、视口、DPR、locale 和颜色模式生成官方/原生配对，并纳入对应 UI TODO 的 `enforce` 验收。

## 已覆盖的失败路径

当前 Swift 测试覆盖 tail/older 的 50-message 约束、连续区间、compaction 边界、空 `hasMore` 守卫、重复/倒序 tail、重复/乱序 older page、tail retry、live duplicate/gap 以及 older-page in-flight coalescing。异常被收敛为 `DSHTransportError` 并显式投影为 `TailState.failed` 或 `OlderState.failed`；既有良好窗口不会在完整性失败时被覆写。

T6.2 不承担 conversation node 的业务解释、渲染、滚动锚点或正式 reconnect rebuilding；这些分别由 T6.4/T6.5、T8.2 以及 T6.7 承担。这个边界防止将未实现 UI 伪装成已验收的分页体验，也防止分页器绕过 Host 真源自行补洞。

## 验证与状态

本地已重跑 D0/D1、模块、OfficialUISpec、locale、WebView 禁止和 visual policy 静态门禁。当前 Linux 执行环境未提供 `swift`/Xcode，因此无法等价执行 macOS 26 Swift XCTest；本提交的 `SessionHistoryPagerTests` 必须由其**自身**的 macOS 26 CI 运行验证，成功后才允许更新 T6.2 的 CI run、证据状态与勾选。若 CI 编译或测试失败，T6.2 保持未完成，并在当前任务修复后重新提交。
