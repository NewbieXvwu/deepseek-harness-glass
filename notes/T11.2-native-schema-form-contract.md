# T11.2：NativeSchemaForm 合同与验证边界

**状态：** 已实现纯原生渲染器与可移植草稿回归；本 TODO 保持未勾选，直至当前提交的 macOS-26 原生构建与 XCTest 取得自身成功证据。

## 1. 官方表单语义映射

锁定官方 `CardForm` 规定所有编辑先在客户端暂存；每一项 settings 写入必须携带 document revision；空文本代表 clear；无效数字阻止保存而不是丢弃草稿；Host readback 才是写入是否成立的唯一权威。
[1] `NativeSchemaFormDraft` 沿用该模型：它只持有 ephemeral staged edit，按 manifest order 输出 `SettingsPathOperationDTO`，
并将 operation 交给现有 revision-fenced Host API。


没有任何控制器可直接修改 durable settings。

官方还将 secret 定义为独立于 settings section 的 write-only control：值不会回到 response 中，初始草稿为空，空值不触发写入。[1] 因而本实现拒绝将 `FieldKind.secret` 解释为 settings path；
仅由 `secretRoles` 通过既有 credentials `set` 回调渲染 `SecureField`。保存失败时 secret draft 保留以供更正，且不制造已配置的假象。

| manifest 元素 | SwiftUI 原生组件/行为 | Host 边界 |
|---|---|---|
| `text`、`number`、`path` | `TextField`；number 仅接受有限 `Double` | `set` 或 `unset` path operation |
| `toggle` | `Toggle` | `JSONValue.bool` set operation |
| `select` | `Picker`；只接受 manifest `options` | 非列举值令整个 mutation plan 无效 |
| `readOnly` | `LabeledContent` 与可选 text selection | 从不进入 mutation plan |
| `secretRoles` | `SecureField` 与状态提示 | 单独 write-only credentials callback |
| `groups`、`helpKey`、`order` | 原生 `VStack`、`Text` 与固定排序 | 不接受 plugin-provided view、HTML 或 closure |
| `reset`、`save`、`discard` | manifest 授权的标准按钮 | reset 输出 inherit/unset；save 只提交 typed plan |

## 2. 安全与兼容边界

`NativeSchemaForm` 的输入不是任意插件 JSON，而是已通过 T11.
1 `NativeUIManifestVerifier` 的值。它从闭合 `FieldKind` 枚举选取 SwiftUI 组件，不能加载 script、plugin closure、HTML、Markdown、WebView 或 runtime renderer。
无法验证的清单应由后续 T11.4 分流器交给 Ghost Plane；本组件不得尝试“尽力”渲染未知 schema。

表单对 secret 与 settings 的分开保存是刻意的、不假装跨 API 原子性。
若一般 settings mutation 成功而 credential write 失败，Host 已接受的 mutation 不会被 UI 伪装为回滚；草稿和失败状态会如实保留。T12.7 仍须把该不可回滚边界与完整插件平面安全审查闭环。
