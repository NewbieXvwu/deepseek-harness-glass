# T5.2 三栏容器来源与证据边界

**任务：** T5.2，实现 AppKit 三栏容器与架构解耦。

**规格来源：** 官方参考源码锁定于 `TODO.md` 的 `deepseek-ai/deepseek-harness@528c682e061696f5a160f363f236ecbf53cbd006`。三栏求解器的直接来源是 `packages/client/ui-layout/src/client/columns.ts`，其中 `CENTER_MIN=640`、sidebar 默认/折叠/最小/最大宽度为 `280/56/264/420`，details 默认/最小/最大宽度为 `360/300/520`；让渡顺序是先压缩 details，再派生关闭 details，sidebar 不让渡，最后由 center 吸收不足。官方行为测试位于 `packages/client/ui-layout/tests/columns.client.spec.ts`。

**原生映射：** Swift 实现位于 `glass/Sources/UI/Shell/NativeSplitContainer.swift` 与 `glass/Sources/Spec/OfficialColumnLayout.swift`。AppKit 的 `NSSplitViewController` 负责原生视图树，SwiftUI 只承载各列内容，不通过 WebView、DOM 或 CSS 注入实现核心 UI。`NativeSplitLayoutPolicy` 将 divider 拖动限制在官方 token 范围内，`NativeSidebarLayoutState` 保存宽窗口偏好，并把窄窗口 rail 展开作为瞬态覆盖；重新变宽时恢复原偏好。

**当前逻辑证据：** `glass/Tests/App/NativeSplitLayoutPolicyTests.swift` 已覆盖官方基线、divider clamp、details 让渡与自动关闭、窄窗口 56px rail、手动展开不污染宽窗口偏好、重复窄窗口刷新以及恢复宽窗口等场景。`glass/Tests/App/WindowCoordinatorTests.swift` 还覆盖窗口协调器复用同一原生 shell controller 的生命周期边界。
