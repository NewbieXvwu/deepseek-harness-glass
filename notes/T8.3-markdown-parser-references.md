# T8.3：Markdown AST 与增量高亮外部参考

本文件记录当前 T8.3 已采用或待采用的外部实现，便于后续依赖升级、API 复核与审计。

| 组件 | 参考版本或状态 | 采用理由 | 来源 |
| --- | --- | --- | --- |
| `swiftlang/swift-markdown` | `0.8.0`，2026-05-07 发布 | 官方 Swift Package；以 GitHub-flavored Markdown 的 `cmark-gfm` 为解析基础，并提供 `Document(parsing:)` 不可变 AST。`GlassUI` 已以 SwiftPM `from: "0.8.0"` 受控接入。[1][2] | [1][2] |
| `tree-sitter/swift-tree-sitter` | `0.10.0`，2026-03-18 发布；待集成 | Tree-sitter 的 Swift API；发行包提供 `SwiftTreeSitter` 与 `SwiftTreeSitterLayer` SwiftPM products，并可与 Neon 结合，用于增量解析。后续必须锁定 grammar 版本、支持的语言集与 macOS 编译路径，再替换当前过渡高亮器。[3] | [3] |
| `ChimeHQ/Neon` | `0.6.0`，2024-01-13 发布；待集成 | 面向内容样式的 Swift 库；其公开说明是基于 SwiftTreeSitter 的同步/异步高亮接口，SwiftPM product 为 `Neon`。仅在解析器和语法包的构建、缓存、取消与内存边界均获验证后采用。[4] | [4] |

> 当前安全边界不依赖任一高亮库：`NativeMarkdownSecurityPolicy` 继续剥离可执行 HTML，只允许绝对 `https`/`http` 链接，并将 `file:`、`data:`、`javascript:` 和相对路径降级为不可激活文本。Tree-sitter/Neon 只能处理代码样式，不能改变链接开放或 HTML 执行策略。

## 依赖兼容性结论

Neon `0.6.0` 的 package manifest 目前直接依赖 `ChimeHQ/SwiftTreeSitter` 的 `main` branch，而本任务指定的是 `tree-sitter/swift-tree-sitter@0.10.0`。[3][4] 两者都以 `SwiftTreeSitter` product/identity 暴露 API，不能在未证明模块、ABI、grammar binding 与 SwiftPM package identity 兼容的情况下同时接入。因而当前实现只先落地与高亮器无关的 `swift-markdown` AST；后续树形高亮必须选择以下已审计路径之一：升级/替换到明确使用指定 upstream API 的 Neon 版本，或使用 `tree-sitter/swift-tree-sitter` 直接实现受限的静态/增量 token adapter。不得以未锁定的 `main` branch 混入第二个同名 Tree-sitter package。

## RC1 官方客户端高亮参考（2026-08-21）

锁定官方 Harness RC1 `packages/client/ui-primitives/src/markdown/highlight.ts` 使用 **Shiki** 生成二维 token-run 结构，并将颜色限制为 `--shiki-*` CSS 变量；未知、缺失或未安全注册的 language 均退回 plain code。其客户端测试覆盖别名、未知 language、流式未完成 fence 与 inherited object-key，避免高亮器崩溃或把未可信 grammar 当作已注册语言。官方当前实现不是 Neon；T8.3 后续应以可锁定 token adapter 或经审计依赖实现等价的 token-run/plain-fallback 契约，不能为满足名称要求接入未验证的 `main` 分支。
