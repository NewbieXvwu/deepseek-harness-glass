## 锁定官方契约

官方 `SettingsRoot` 自行持有 panel open/close 与 active section ID。它通过有序 settings section ledger 取得导航 rows；关闭面板必须同时关闭并清除 active ID，`openSection` 则设置该 ID 并打开面板。用户主动打开而无 selected section 时，panel 由列表第一项成为活动项；活动 entry unregister 后同样回落到 first row。[1]

面板以 dialog 语义组织：header slot 的 ID 是 dialog 的 accessible name，shell-owned close 按钮通过 visually-hidden close slot 获取名称，header action seat 位于 close 控制之前。mask click、header close 和 document-level Escape 都关闭 panel；打开时焦点进入 close 控制。导航每项以 section ID 激活、独立 glyph、`aria-current` 标记，并只挂载当前 section；空 ledger 保持空 content column，不伪造产品 section。[1]

| 契约 | 当前原生映射 | 未闭环边界 |
|---|---|---|
| 官方 locale section label | `NativeSettingsRoot.SectionID` 的 general/models/plugins/agent presets 标题只读取 `OfficialUISpec.LocaleCatalog` | 需复核所有官方 builtin sections、locale reload 与 current-SHA runtime。 |
| settings Host authority | `NativeSettingsStore` 管理 schema/value/base/user/applies/secrets/revision 与 expected revision write fence | T10.2/T10.3 保持其表单和凭据细节验收。 |
| root navigation / selected state | `NativeSettingsRoot` 已有 section ID 与测试锁定的初步 nav 映射 | 仍须对齐官方 dialog close/reset/Escape/focus、fallback/unregister 和视觉 geometry。 |
| onboarding ownership | 原生不得自建额外 settings overlay chrome | 必须以独立官方来源确认本地 onboarding 接入后再做可见性声明。 |
