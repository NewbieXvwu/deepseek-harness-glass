**官方基线：** `deepseek-ai/deepseek-harness@b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`（`dsh-v0.1.1-rc.2`）。本文只记录 settings trigger、section ledger、panel chrome与导航所有权，不能以源码或上游测试替代本项目 current-SHA 的 macOS-26 AppKit runtime、AX或visual证据。

## rc.2 锁定契约

官方 `SettingsRoot` 自行持有 `open` 与 active section ID：`close`同时关闭并清除active，`openSection`同时设置section并打开panel。以有序section ledger生成nav rows；用户无显式选择地打开或当前entry注销时，panel回退到first row；ledger为空时仅渲染空content column，不伪造产品section。[1]

> SettingsPanel的dialog accessibility name来自header seat ID；shell-owned close button使用`settings.close` seat的可见性隐藏label。打开时焦点直接落到close button，mask、header close和document Escape均关闭panel。[1]

| 契约 | 当前原生映射 | 仍待闭环 |
|---|---|---|
| settings trigger dialog state | 官方trigger是`type=button`，具有`aria-haspopup="dialog"`和随open更新的`aria-expanded`；click只设置open，close才清active。 | Native sidebar将真实`settingsPresented`注入settings button并以SwiftUI可用的`.accessibilityValue("false"/"true")`导出close/open状态；macOS AX seam覆盖两值。SwiftUI Button没有等价的显式has-popup或expanded modifier，仍需current-SHA AX tree人工确认其window/dialog关系而不虚称HTML属性。 [1] |

| mask/close/Escape | 官方web panel在同一document overlay中以`aria-hidden` mask的click调用同一`close`，header close与document Escape也同样关闭并清active。Native选用独立`NSWindow`，没有可点击的同document遮罩；它通过toolbar close与`windowWillClose`回写`settingsPresented=false`，由AppKit closable window承担Escape/cancel。不得为视觉表面相似而在独立窗口外自创mask。 | current-SHA close/Escape集成测试与window activation/阻断行为工件。 [1] |

2026-08-22 已在Node `24.19.0`、pnpm `11.7.0`下运行rc.2 `packages/client/ui-settings-general/tests/settings-root.client.spec.tsx`，**17项测试通过**。它覆盖trigger accessible name/rail、dialog label、header actions/close、mask/Escape/focus、first-active/switch/unregister fallback/empty ledger和onboarding ownership；仅为官方行为来源，不替代native验收。[2]

2026-08-22 已新增Foundation-only `NativeSettingsSectionLedger`和`NativeSettingsSectionLedgerTests`：相同order保持registration sequence、显式active仅在仍存在时保留、nil/已注销entry回退有序first、空rows与close均返回nil。`NativeSettingsRoot`使用该投影登记四个rc.2 builtin id（包括精确`agent-presets`连字符ID），而非`CaseIterable`直接决定导航。`portable-checks`亦以独立Swift CLI harness执行同一production source；Linux完整SwiftPM XCTest会在`GlassSpec`需要AppKit时失败，这是平台缺失而非ledger compile/test failure，macOS-26 `native-ui`仍是Core XCTest与原生界面的权威门禁。

## rc.2 onboarding ordered ownership

官方Models feature登记`welcome-notice`（order `-100`）和`deepseek-official`（order `0`）。SettingsRoot仅在Host session ready且current为空或blank时选取第一个未完成step；其`complete`回调绑定当前step ID，离开welcome session后清空in-memory completed set。shell不拥有dialog chrome或inert mask；step的private readiness仍在loading时必须render `null`，并由step自行拥有可见modal、focus及complete路径。[3] [4]

`NativeSettingsOnboardingLedger`现只实现这一不含UI的ownership投影：stable registration order、welcome-state门控、first pending、仅active step可complete与inactive reset。Core XCTest和portable CLI harness覆盖上述纯决策。当前原生没有官方Models join（provider usable、active、credential reference/error与settings writable的同一快照），亦没有`welcome-notice` acknowledgement remote store；因此不得把`NativeModelDirectoryStore`的目录、`NativeCredentialStore`的单ref状态或本地文案猜测为官方readiness，也不挂载空modal。后续必须先建立该typed join与ack authority，才可原生实现两个step及其step-owned chrome。[4] [5]
