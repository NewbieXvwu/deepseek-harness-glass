# T6.6 Trajectory target snapshot：RC8 来源与原生边界

> **锁定规格来源**：`deepseek-ai/deepseek-harness@141eb6fef83422698aef7a981029e843e8161534`。

RC8 将 Chat 与 Trajectory 注册为独立 `conversation.view` 目标；trajectory message definition 使用自己的 target/key，并由 trajectory snapshot builder 消费相同权威 history/event 窗口。[1][2] 原生 `ConversationCoreNodeRegistry` 已有 `TrajectoryMessageDefinition`，但此前 `NativeSessionStore` 只发布 `chatNodes`，使任何原生 trajectory contribution不得不接触 reducer internals或重放 raw history。

本小项新增只读 `trajectoryNodes` published snapshot，并在 `resetConversationWindow`、`replaceConversationWindow`、`prependConversationWindow`、`appendConversationEvent` 与 Chat 同步更新它。`NativeSessionStoreTests` 使用版本化 tooling fixture 验证 Chat 与 Trajectory targets 的 node/key隔离：fixture user message出现在 `trajectory-input-message`，而 assistant/chat materialization仍留在 Chat target。

这不是完整 Trajectory view：toolbar、ledger table、tool rows、selection/details、search/collapse、官方 screenshot/ARIA和 macOS GUI证据仍由后续 renderer/visual子项闭环。该 Core surface只向 native contribution registry提供已 typed、reducer-owned数据，绝不暴露 raw Host event 或以 Chat nodes替代 trajectory chronology。
