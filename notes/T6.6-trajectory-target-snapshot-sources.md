# T6.6 Trajectory target snapshot：RC8 来源与原生边界

> **锁定规格来源**：`deepseek-ai/deepseek-harness@141eb6fef83422698aef7a981029e843e8161534`。

RC8 将 Chat 与 Trajectory 注册为独立 `conversation.
view` 目标；trajectory message definition 使用自己的 target/key，并由 trajectory snapshot builder 消费相同权威 history/event 窗口。
[1][2] 原生 `ConversationCoreNodeRegistry` 已有 `TrajectoryMessageDefinition`，但此前 `NativeSessionStore` 只发布 `chatNodes`，
使任何原生 trajectory contribution不得不接触 reducer internals或重放 raw history。




本小项新增只读 `trajectoryNodes` published snapshot，
并在 `resetConversationWindow`、`replaceConversationWindow`、`prependConversationWindow`、`appendConversationEvent` 与 Chat 同步更新它。



resident session state 现同时保存/恢复 `chatNodes` 和 `trajectoryNodes`：restore 先从原始 reducer window重建后续 Host输入所需的内部状态，
再恢复保存的 typed target snapshots供立即呈现，绝不以 UI snapshot取代 reducer evidence。


`NativeSessionStoreTests` 使用版本化 tooling fixture 验证 Chat 与 Trajectory targets 的 node/key隔离及 session switch后两者的对称恢复：fixture user message出现在
`trajectory-input-message`，


而 assistant/chat materialization仍留在 Chat target。

`NativeShellPresentation` 现将 `trajectory` 以 order `10`、官方 `ui-trajectory.
view.trajectory` 文案注册到 window-resident `NativeConversationViewRegistry`。
`NativeTrajectoryView` 只显示 target-owned、typed `CoreUserMessageNode` list；
其内容绝不访问 raw Host event，也不把 Chat nodes当作 trajectory chronology。
`NativeConversationHeaderTests` 锁定 built-in tab 的 `[chat, trajectory]` 顺序、官方标签、selection解析与 renderer可用性。

`SnapshotExporter` 的 `DSH_GLASS_SNAPSHOT_MODE=trajectory` 复用版本化 tooling fixture，并在构造 window-resident shell前选择 `trajectory` target。
它只提供同状态 native light/dark capture入口，未提供官方基线、差异分类或可替代 toolbar/ledger/ARIA 验收的证据。

这不是完整 Trajectory view：toolbar、ledger table、tool rows、selection/details、search/collapse、官方 screenshot/ARIA和 macOS GUI证据仍由后续
renderer/visual子项闭环。




该 Core surface只向 native contribution registry提供已 typed、reducer-owned数据，绝不暴露 raw Host event 或以 Chat nodes替代 trajectory chronology。
