# T6.7：RC8 reconnect/replay 官方来源与恢复约束

**锁定上游：** `deepseek-ai/deepseek-harness@141eb6fef83422698aef7a981029e843e8161534`。

RC8 的 `ConversationNodeAssembler` 是 **session-owned** 的连续事件窗口装配器，而不是消息数组缓存。[1] 重连、Host 重启、history gap 修复和 cold-to-live 都必须重新建立 Host authority window；原生端不得把旧的局部 view state 当作新的history authority。

| 官方路径 | RC8 行为 | NativeSessionStore 对应约束 |
| --- | --- | --- |
| `replaceWindow(entries, hasMore)` | 清空 contexts、输入、依赖、dirty/revised；按 seq 排序完整重建 location index、match 和依赖，然后强制一次整体 materialization | authority history baseline 落地、gap repair或generation无法连续时，必须调用 `replaceConversationWindow`，并同时按baseline更新projection；不得将新window append到旧reducer |
| `append(input)` | 忽略重复seq；边界事件重算受影响location与dependent context，普通live event增量匹配；只重放revision受影响的依赖 | 确认连续的实时 `session/event` 才能经 `appendConversationEvent` 进入现有window；旧/重复序列不可重新materialize |
| `prepend(entries, hasMore)` | 仅插入尚未存在的older event，重建location，合并match并重放受影响依赖，保留已有context identity | `loadOlderHistory` 的合法连续page使用 `prependConversationWindow`；无效range、重复或gap不允许伪造历史 |
| `replayDependencies()` | predecessor key/revision/window-gap 变化时重新执行context start，再逐update replay | history authority替换与older-page插入必须由reducer完成依赖重放；UI不得手工重新分类steering/trajectory/workflow |
| `session/projection` baseline | history tail projection 是同一authority cut；live更新不能被较旧baseline覆盖 | history response 的 `projections` 只能用`SessionProjectionStore.seed`，且在generation新`lastSeq`时先truncate高水位外行 |

## 当前原生恢复缺口

`NativeSessionStore.open` 已在 cold/resident session 选择时通过 `session.models`、`session.history`、projection seed 和mux订阅建立一轮authority。`SSEClient.reconnectingStream` 能重开物理流并对RPC ID/序列去重，`session/subscribed` 当前会清空generation-bound queue/jobs/approval/question并截断projection。然而 **transport成功重开本身尚未触发一次history/status authority refresh**；因此T6.7须增加有generation和active-session fence的恢复协调器，避免将只重开socket误认为完整replay。

## 必须满足的恢复算法

1. 每次cold open、已检测gap、Host generation变化或transport恢复都建立唯一`RecoveryGeneration(sessionID, endpoint, token)`；旧Task在任何await后均须验证token、active session和endpoint。
2. recovery按Host顺序读取`session.models`、tail `session.history`和其projection baseline；只有同一generation仍current时才原子替换conversation window、seed projection并恢复phase。
3. queue/jobs/approval/question只能等待新的mux whole snapshot/ServerRequest，不得从history补造；新`session/subscribed`先清除前代暂态。
4. consecutive live frame可在恢复完成后append；重复、低序或无法证明连续性的event必须请求完整baseline，不能局部merge。
5. session切换、disconnect、Host endpoint变化和新的recovery请求必须取消前代recovery，并保证旧错误、models、history或projection结果都不能覆盖新session。
6. 回归以每个断点（turn/step boundary、chunk、tool call/result、projection、queue/jobs、approval/question）分别构造连续参考与断线恢复参考，比较typed window、chat node key/visibility、projection、extension state与可操作pending request，不比较源码文本。
