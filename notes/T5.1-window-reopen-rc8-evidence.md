# T5.1：窗口重开策略与 RC8 重新认证记录

本记录对应 `WindowCoordinator` 的原生窗口生命周期。锁定官方基线仍为 `deepseek-ai/deepseek-harness@141eb6fef83422698aef7a981029e843e8161534`；
官方 WebUI 只规定三栏应用表面而不拥有 macOS `NSWindow` 生命周期，因此窗口创建、隐藏、最小化与 Dock reopen 使用 AppKit 标准行为，并服从项目 D0–D3 边界。

## 本次行为加固

`WindowCoordinator.showAndFocus()` 现在保留只读调用计数，作为不创建第二个 shell 的运行态测试 seam。
`DeepSeekHarnessGlassApp` 接受注入的 `WindowCoordinator`，并把 `applicationShouldHandleReopen(_:hasVisibleWindows:)` 委派到这一已有实例。
该方法仍保持原来的行为：当窗口存在时解除最小化、置前和激活；当窗口尚未安装时则不制造新的 shell。

`WindowCoordinatorTests.
testDockReopenDelegatesToTheExistingCoordinatorWithoutCreatingAShell` 以实际 `NSApplication` delegate entry 调用 Dock reopen，
断言：协调器调用次数恰为一次、生命周期变为 visible、且 `window` 保持 `nil`。


这构成“没有额外窗口创建”的负向可证伪条件，而不是仅检查某个源码关键字。

| 路径 | 原生行为 | 当前证据 |
|---|---|---|
| 红色关闭按钮 | 保存同名 native frame 后 `orderOut`，保留菜单栏可达性。 | 既有 `WindowCoordinatorTests` 生命周期断言；仍待当前 SHA macOS CI。 |
| Dock reopen | 委派现有 `WindowCoordinator.showAndFocus()`，不重建 shell。 | 新增调用计数与 `window == nil` 回归。 |
| 最小化后 reopen | `showAndFocus()` 先 `deminiaturize`，再 key/order front。 | 既有纯生命周期断言；仍待当前 SHA macOS CI。 |

## 未完成证据

本地 Ubuntu 只能执行 Swift 语法解析、格式和可移植结构门禁，不能运行 AppKit/XCTest 或捕获 WindowServer 截图。
T5.1 继续保持未勾选，直至当前代码提交的 `macos-26` 工作流成功执行 `WindowCoordinatorTests`，并重新核对 RC8 snapshot 的窗口尺寸、titlebar policy、close/reopen 可达性和系统材质分类。
