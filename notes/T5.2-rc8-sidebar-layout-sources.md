# T5.2：RC8 三栏侧栏状态机来源与实现映射

**官方基线：** `deepseek-ai/deepseek-harness@141eb6fef83422698aef7a981029e843e8161534`（`dsh-v0.1.0-rc.8`）。本记录只覆盖本次补充的窄窗口侧栏状态机；它不是 T5.2 或 T7.4 的视觉验收结论。

## 官方契约

官方 `columns.ts` 将侧栏收缩 rail 固定为 **56px**，并定义 `SIDEBAR_AUTO_COLLAPSE = 1024`；三栏 solver 本身不含断点逻辑，而由 `AppFrame` 决定有效 sidebar preference。[1] 在 `AppFrame.tsx` 中，`viewport < SIDEBAR_AUTO_COLLAPSE` 时默认收缩；用户在窄窗口执行展开时，组件使用 `narrowExpanded` 覆盖默认收缩，并将原有宽窗口 preference 保持不变。[2]

官方 `stores.ts` 将这一语义明确为状态对 `narrow` / `narrowExpanded`：窄窗口下 `toggleSidebar` 只翻转 `narrowExpanded`，跨越断点时 `setNarrow` 清除该临时覆盖；宽窗口才实际写入 sidebar preference。[3]

| 官方状态/动作 | 原生映射 | 保持的可观察语义 |
|---|---|---|
| `narrow = false` | `NativeSidebarLayoutState.isNarrow = false` | 使用持久的宽窗口收缩偏好。 |
| `narrow = true` | `setNarrow(true)` | 默认渲染 56px rail，并清除上一次窄窗口临时覆盖。 |
| `narrowExpanded = true` | `setCollapsed(false)` 在窄窗口的映射 | 允许窄窗口暂时展开，但不改写宽窗口偏好或拖拽宽度。 |
| 断点返回宽窗口 | `setNarrow(false)` | 清除临时覆盖并恢复原宽窗口收缩偏好。 |

## 原生实现与回归

`glass/Sources/UI/Shell/NativeSplitContainer.swift` 现在以 `NativeSidebarLayoutState` 统一保存窄窗口和宽窗口语义。`NativeShellController.viewDidLayout` 与 `renderPresentation()` 均把当前视口宽度写入该状态机，随后使用其派生的 `isCollapsed` 配置 `NSSplitViewController` 的 sidebar item。`NativeSidebarView` 的展开/收起回调通过 `NativeShellPresentation.setSidebarCollapsed(_:)` 进入同一状态机，避免在窄窗口直接改写宽窗口 preference。

`glass/Tests/App/NativeSplitLayoutPolicyTests.swift` 新增两条回归：其一验证默认窄窗口收缩、手动展开、重返宽窗口后恢复未修改的宽窗口偏好；其二验证已手动收缩的宽窗口在窄窗口临时展开后，重返宽窗口仍保持收缩。
