## Result-side admission 与 recovery

search card 是 **result-side only**：running search 没有 result view，必然显示 generic running；settled call 只有 `resultView.card == 'search'` 才可能进入 card。`shape:'matches'` 还必须有合法 grouped `files`，`shape:'paths'` 必须有全 string `paths`；未知 shape、缺失/错误结构、generic或unknown card都返回 null并保留 raw generic result。[1]

`truncated` 时才提取 flattened raw result为 recovery footer，未截断时 recovery 必须为 undefined。replacement `title` 是 card外的名称输入；structured card本身携带 `truncated` 与 pre-cap `total`。[1]

| 状态 | 专用卡 | generic fallback |
|---|---|---|
| running grep/glob | 无 | details.running / row generic |
| settled valid matches | grouped files and matches | 不适用 |
| settled valid paths | flat path list | 不适用 |
| capped valid search | card + recovery locator | 不适用 |
| generic/unknown/malformed/error | 无 | flattened raw output/error |

## SearchBlock primitive矩阵

matches以 file header（可折叠、count）与 `lineNumber: line` row flatten；paths为flat path row。height cap应用于flatten rows而不是匹配数量。若 capped tail从某file的match开始、且head没有该file header，primitive恢复对应header并让其占一个tail slot，维持总可见row不超过cap。所有source/paths no-wrap且横向滚动。copy包含整个structured result，忽略cap和collapsed状态；empty result显示 `无结果` 且没有copy。banner summary在truncated时写 `显示 X / 共 N …`，否则只显示retained count。[2]

## Native尚未实现边界

native当前未有 search adapter、matches/path projection、tail-header repair、collapse state、summary/recovery/copy/chrome或8/16 cap。下一增量必须先建立Foundation-only schema validation与row flatten/recovery rule，再接入SwiftUI；任何非admitted view继续generic fallback。因此 **T9.2继续未勾选**。

## Native projection、recovery与row/details接入（2026-08-22）

本轮新增 `NativeToolSearchViewAdapter`：仅接纳 `card:'search'`、已知 matches/paths shape、boolean truncated、有限非负 total，以及每个 matches group的string path/array matches或全string paths。未知shape、malformed group/line/path、generic和running都无法产生 `NativeSearchCardPresentation`。Core `ToolInvocation.textOutput` 另行保存official `flattenContent`所需的text-only blocks；它不使用generic `output`内的non-text pretty JSON或empty error fallback，且只有truncated card接收recovery。

`NativeSearchRowsPresentation`/`NativeSearchWindowPresentation`复刻group collapse、flat paths、head/tail cap以及tail开始于match时的owner header repair。原生 `NativeSearchToolCardBody` 已按官方 ToolRow的terminal→diff→read→search和ToolDetails的terminal→read→diff→search顺序接入，使用官方literal summary/empty/expand chrome、code block tokens、8-line row/16-line details cap、no-wrap horizontal rows、file collapse、copy全structured result与text-only recovery。selected details card以call ID identity重置copy/expand/collapse state。

`NativeSessionStoreTests` 验证 `textOutput`只保留text blocks，`NativeToolSearchViewAdapterTests`和portable harness覆盖schema/recovery/tail-header，`NativeAccessibilityRuntimeTests.testTypedSearchDetailsExportsSummaryRecoveryAndMatches`注册macOS AX seam。尚未有此提交current-SHA macOS-26编译/XCTest/runtime、copy/collapse/expand互动、running/generic negative runtime scene、paired visual或人工差异分类；T9.2保持未完成。
