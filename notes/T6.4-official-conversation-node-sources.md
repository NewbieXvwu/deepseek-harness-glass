## 范围与视觉边界

`ConversationNodeDefinition` 与 `ConversationNodeReducer` 是 Core 层的 session-owned event-to-node 状态机。
它们接收已验证的 `SessionEventDTO`、保留可选 Host wire view、请求 publication cadence、读取由 engine 维护的 session/turn/step location，
并 materialize target-neutral `ConversationViewNode`。


协议本身不导入 SwiftUI/AppKit/WebKit，不包含官方产品文案、视觉 token、布局或截图逻辑；任何 SwiftUI renderer 只能消费已 materialize 的 node，不能解析 raw event body。

> 因此 T6.4 采用 Core-only 边界审阅，而不以尚未完成的 ChatView 假造视觉验收。待 T8.2 呈现这些节点时，
> 用户可见的历史/streaming 状态仍必须在相同官方 fixture、视口、DPR、locale 和颜色模式下完成官方/原生配对及 `enforce` 验收。

## 新增逐事件重放证据

本次补充的 `ConversationNodeTests` 不只检查 type erasure，
而是以一个连续 window replay 验证 engine-owned location：turn/start、step/start、业务 match、step/end、turn/end 一次性进入 reducer 后，
业务 definition 只读取 `ConversationMatch.


location`，得到已关闭的 turn 与 step 状态；它没有解析或扫描整个 timeline。这与官方由 location index 建立事实、definition 消费事实的职责划分一致。

另一新增测试注册两个同时匹配同一 raw event 的 definition，分别请求 `animationFrame` 与 `immediate` publication；
reducer 必须返回 `immediate` 并在各自 target materialize 一个稳定 node。
该用例证明 publication 是 reducer 事务的最大值，而不是任一 renderer 对 raw event 的私有刷新决定。
