# T6.6：Conversation Core 空文本 XCTest 编译修复

## 触发事实

`main` 的 macOS-26 `native-ui` 工作流运行 `32501128617` 在编译 `ConversationCoreNodesTests` 时停止。失败位置为 `glass/Tests/Core/ConversationCoreNodesTests.swift:47`：断言对 `CoreAssistantBlock.text`（`String?`）直接调用 `contains("plan")`，而当前编译器正确要求先处理可空值。

## 最小修复

测试改为 `text?.contains("plan") ?? false`。因此，任何包含 transient reasoning 文本 `plan` 的 block 仍会使断言失败；没有文本的非文本 block 则不会被错误当作 reasoning。生产 reducer、Host RPC/SSE 契约、官方 locale、UI renderer 和可观察布局均未变更。

## 规格关联与验证边界

锁定官方 Harness 的 runtime session 实现将 `assistant/chunk` 的 `reasoning-delta` 与 `text-delta` 累积为 partial block，并在紧随其后的 `assistant/message` 最终消息到达后取代 partial 内容。该回归保持对这一“final message 不泄漏 transient reasoning”的 Swift 投影断言。
