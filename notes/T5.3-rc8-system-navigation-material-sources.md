# T5.3：RC8 系统导航材质结构证据

**官方基线：** `deepseek-ai/deepseek-harness@528c682e061696f5a160f363f236ecbf53cbd006`（`dsh-v0.1.1-rc.1`）。本记录覆盖系统 sidebar/inspector 宿主的原生结构边界，而不把 macOS 系统材质与网页 CSS 像素做错误的一一比较。旧 RC8 commit 仅保留历史演化记录，不能作为当前验收来源。

## 官方可见结构

官方 RC8 `AppFrame` 固定渲染 sidebar、center 和 details 三个列位置；details 关闭时保留 subtree，但将宽度派生为零。[1] 官方 CSS 给 sidebar 一个右侧边界、details 一个左侧边界，并在 details 收缩时移除其 1px seam；sidebar 收缩 rail 则持续保留边界。[2]

| 官方结构 | 原生结构 | 本次运行态断言 |
|---|---|---|
| sidebar column | `NSSplitViewItem(sidebarWithViewController:)` | 第一个 item 的 `behavior == .sidebar`。 |
| center content column | 普通 `NSSplitViewItem` + SwiftUI conversation host | content host subtree 不含 ad-hoc `NSVisualEffectView`。 |
| details column | `NSSplitViewItem(inspectorWithViewController:)` | 第三个 item 的 `behavior == .inspector`。 |
| details 收缩边界 | `OfficialColumnLayout` 与 `detailsItem.isCollapsed` | 保留给 T5.2/T5.3 macOS layout 和 paired-scene 验证。 |

## 新增可证伪测试

`NativeMaterialIsolationRuntimeTests.testNativeShellUsesSystemSidebarAndInspectorItemsWhileContentStaysMaterialFree` 实际创建 `NativeShellRootController`，解析其真实子控制器树，并断言：存在三项 split item，第一项为 AppKit sidebar，第三项为 AppKit inspector，中心 conversation host 不含自定义 `NSVisualEffectView`。该断言避免以源码关键词或静态声明替代运行态结构证据。

现有注入 `NSVisualEffectView` 的负例继续证明递归树检测确实能拒绝违规结构。

## 2026-08-22：当前锁定基线复核

已直接复核 `528c682e` 的 `AppFrame.tsx` 与 `AppFrame.module.css`。其固定三栏、details 零宽仍挂载、sidebar 右边界与 details 左边界、details collapsed 时移除 seam 的规则保持存在；原生 `NativeSplitViewController` 仍使用系统 `.sidebar` / `.inspector` split item，`TransparentHostingController` 仅设非 opaque clear backing、不创建 `NSVisualEffectView` 或自定义模糊。该结构复核不把 Web CSS fill/border token 移植为自创 macOS 材质，也不替代当前 SHA 的 AppKit runtime、系统辅助功能条件与同状态配对证据。
