## 已核验的上游依据

| 官方文件 | 采用的核心语义 | 本地映射 |
|---|---|---|
| `packages/client/runtime/src/client/contract/conversation.ts` | 事件经 Session-owned definition/assembler 形成稳定的 target node；定义只读取 location、publication 和上下文。 | `ConversationCoreNodeRegistry` 注册 Core definitions；所有 UI 仅消费 `ConversationViewNode`。 |
| `packages/client/runtime/src/client/sessions/conversation-assembler.ts` | append/prepend/replace 的单一事务边界、严格 seq、match lifecycle、最大 publication 与 materialized target snapshot。 | `ConversationNodeReducer` 负责 raw window、稳定 key、target snapshot 与 publication 归并。 |
| `packages/client/ui-conversation/src/client/conversation-nodes/assistant.ts` | `step/start` 创建 assistant-step；chunk 追加 blocks；append-surface final message settled；retry 重置；closed boundary 生成 interrupted synthetic anchor；可见性由块内容决定。 | `AssistantStepDefinition` 的 chunk/final/retry 分支、`CoreAssistantNode` 状态、`closedEvent` 和 `anchor - 0.9`。 |
| `packages/client/ui-conversation/src/client/conversation-nodes/tool.ts` | tool call/result 以 call ID 关联；无 result 的关闭边界转为 interrupted。 | `ToolDefinition` 以 `callId` 建 context，result message source 回写，使用 `anchor - 0.8` 的 interrupted payload。 |
| `packages/client/ui-conversation/src/client/conversation-nodes/retry.ts`、`turn-error.ts`、`compaction.ts` | retry/turn error、compaction summary/checkpoint 保留各自稳定 identity，并以官方事件相关字段更新或隐藏。 | `RetryDefinition`、`TurnErrorDefinition`、`CompactionDefinition` 和相应 typed Core payload。 |
| `packages/client/runtime/tests/conversation-assembler.client.spec.ts` | 官方验证 append 只更新精确 business-id context、长上下文不重放无关 context、older history 重放受影响 context。 | `ConversationCoreNodesTests` 的初始 node tests 与新增的每事件 append 快照序列。 |

## 当前逐 append 回归

`testCoreNodeReplaySnapshotsRemainStableAfterEveryOfficialAppend` 以连续 raw event 序列重放：turn/start、step/start、append user message、两次 assistant text delta、tool call、append tool result、append final assistant message 和 step/end。每次 append 后记录 chat node kinds，同时断言 publication cadence、稳定 assistant/tool 行数、final payload 与完整 raw seq window。

该测试避免由静态最终快照掩盖 streaming 更新、tool result 关联或 final message 重排。用户可见 Chat renderer 尚由 T8.2 实现，因此 T6.5 仅可接受 Core-only 边界审阅；后续 UI 必须使用同一事件 fixture 完成官方/原生同状态视觉配对。
