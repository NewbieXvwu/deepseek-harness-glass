## 当前逐 append 回归

`testCoreNodeReplaySnapshotsRemainStableAfterEveryOfficialAppend` 以连续 raw event 序列重放：turn/start、step/start、append user message、两次 assistant
text delta、tool call、append tool result、append final assistant message 和 step/end。
每次 append 后记录 chat node kinds，同时断言 publication cadence、稳定 assistant/tool 行数、final payload 与完整 raw seq window。

该测试避免由静态最终快照掩盖 streaming 更新、tool result 关联或 final message 重排。
用户可见 Chat renderer 尚由 T8.2 实现，因此 T6.5 仅可接受 Core-only 边界审阅；后续 UI 必须使用同一事件 fixture 完成官方/原生同状态视觉配对。

## CI 失败关闭记录

提交 `58e0b80` 的 macOS-26 [run 32267627825](https://github.

失败不是生产实现或编译问题：测试错误地预期 `turn/start` 为 `none`，而本地 `TurnErrorDefinition` 对该 start 的默认 publication 为 `immediate`；
这与官方 assembler 对 location boundary 变化立即发布的事务语义一致。修复后的预期将首个 publication 更正为 `immediate`，并必须由新的 macOS-26 run 重新验证。T6.5 在新 run 成功前保持未勾选。
