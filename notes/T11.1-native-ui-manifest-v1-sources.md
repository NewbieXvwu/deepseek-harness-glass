# T11.1：NativeUIManifest v1 官方来源与实现边界

**状态：** 已完成声明式模型、JSON Schema、负例回归与 Linux 独立验证；任务本身仍保持未勾选，直至本实现提交取得自身 macOS-26 权威构建与测试证据。

## 1. 来源结论

锁定官方插件设置模块以 **Host 已服务的 settings namespace** 作为卡片调度边界：未被当前 Host composition 服务的 namespace 不得显示占位卡片；卡片的顺序由注册顺序决定；草稿在客户端暂存，但 revision-fenced 写入是否成立只能由 Host readback 决定。[1] 这意味着原生声明模型只能表达受审阅的静态字段、顺序、能力与写入意图，不能把任意插件源码、动态 UI 函数或 Host response 当作可执行表单。

官方动态 Cordis 客户端运行时以稳定 `pluginId`、不可变 `packageId`、精确 `pluginRunId` 和 session/agent identity 标识一次激活；它通过模块表、loader 与 `SlotRegistry` 管理插件浏览器半区，并将运行时加载与渲染故障明确分类。[2] 因此，原生清单的 `pluginID` 与 `hostBuildRange` 仅是 native fast-path 的可审计选择条件，绝不替代动态插件运行时的身份与故障归属语义。

项目已合入的 Ghost Plane 提案将受审阅的 `NativeUIManifest` / `SwiftAdapter` 定义为精品原生快车道；无法验证、未适配或不应由 native 直接承载的插件，将由后续分流器转至独立的登记制绿区插件平面，而不得产生局部、猜测性原生表单。[3]

| 官方/项目来源 | 锁定位置 | v1 映射 |
|---|---|---|
| 插件设置 namespace、卡片顺序、草稿与 revision writeback | `packages/client/ui-settings-plugins/README.md` | `pluginID`、sections、fields、order、actions、requiredCapabilities；不承诺本地写入成功。 |
| 动态插件身份、模块 loader、slot lifecycle、失败分类 | `packages/extensions/cordis-client-runner/src/client/runtime.ts` | Host build 与 integrity 作为 native fast-path admission；不重写 `pluginRunId`/slot 运行时。 |
| Ghost Plane 的快车道与红/绿区边界 | `docs/PLUGIN_COMPATIBILITY_PROPOSAL.md` | 所有验证失败均返回 `ghostPlaneFallback`，不创建半完成 native form。 |

## 2. v1 数据与验证合同

`NativeUIManifest` 位于 `GlassCore`，避免让其依赖 SwiftUI、WebKit 或插件宿主。它完整声明 `pluginID`、固定 Host build range、`manifestVersion`、kind、locale resources、sections、fields、groups、order、secret roles、validations、actions、required capabilities 和 integrity。配套 `native-ui-manifest-v1.schema.json` 使用 JSON Schema Draft 2020-12 发布等价的非可执行输入约束。

版本治理采用 **显式迁移而非宽松比较**。v1 只接受 `manifestVersion == 1`，并要求 minimum/maximum Host build 都精确等于本项目的锁定 `OfficialUISpec.Build.id`。任何将来 Host 或 schema 变化均须引入新的清单版本、完成官方来源复核并增加迁移回归；不能通过字符串前缀、语义版本猜测或用户给出的范围扩大原生兼容面。

完整性验证属于受信任的 Host/隔离平面边界。清单本身声明 `sha256`、digest 与官方 source commit，但 verifier 只接受由外部已验证边界传入且逐字段相等的 integrity 值。算法、digest 格式、source commit、Host build、locale 资源、引用关系、field path、secret field 或版本任一条件失败时，验证器均返回 `ghostPlaneFallback`，不把不可信数据解释为 native UI。

## 3. 验证资产

`NativeUIManifestTests` 覆盖受验证清单进入 native route、未知版本/Host build、缺失或格式错误的 integrity、secret field、缺失 field 引用及 JSON Schema resource。由于完整 `GlassSpec` 依赖 macOS `AppKit`/SwiftUI，另设 `glass/ci/native-ui-manifest-portable-check.swift`：它以最小锁定-spec seam 在 Linux 直接编译生产 `NativeUIManifest.swift`，并验证 verified 通过、unverified integrity 与 secret field 均 fail closed。该程序已通过；同一命令已纳入 `portable-checks`。

> 这不是 T11.2 的动态表单实现，也不授予任何未知插件 native 解释权。T11.2、T11.3 与 T11.4 仍须分别完成 native rendering、adapter registry 和 Host/green-zone routing 后再行验收。
