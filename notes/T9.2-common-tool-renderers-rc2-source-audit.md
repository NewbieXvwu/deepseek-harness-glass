# T9.2 常用 Tool Renderer：rc.2 当前来源审计

**官方基线：** `deepseek-ai/deepseek-harness@b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`（dsh-v0.1.1-rc.2）。

> 本文记录官方实现和可复现的上游契约结果。它不替代本项目 current-SHA 的 macOS-26 编译、XCTest、运行态、视觉、键盘或无障碍证据。

## 官方 renderer 分层

官方 `tool-call-model.ts` 将冻结的 running/settled tool call 投影为稳定 row model。它负责 variant、title、summary、可打开的 file path、展开输入 body、flattened output、error summary 与状态；各专用 card 不能各自重新猜测同一份 payload。[1]

| 官方层 | 责任 | 原生实现约束 |
|---|---|---|
| `tool-call-model.ts` | `bash`、`read`、`search`、`write`、`edit`、`code`、`others` 分类；summary key 优先级；非 JSON raw fallback；running/stopped/error/ok 状态。 | `NativeToolRowModel` 必须从同一 typed invocation 派生摘要，未知 tool 保留 tool name 与 raw payload，不得以假定专用视图吞掉内容。 |
| `TerminalBlock`、`ReadBlock`、`SearchBlock`、`DiffBlock` | 展示已判定的 terminal/read/search/diff 内容。 | 专用 SwiftUI card 只能由明确 typed presentation decision 接管；未匹配时退回 generic raw body/output。 |
| `ToolRow`、`ToolCallTree`、`tool.call.toolview` | keyed row seat、whole-row expand 和 plugin-specific renderer registration。 | 原生 selection/expand 必须保持 keyed invocation identity；专用 renderer 不得破坏 generic fallback。 |
| `ToolDetails` | terminal → read → diff → search → web 的详情 card 选择；running 仅显示官方 details-running；其余 settled output 显示 flattened raw result。 | `NativeToolDetailsBody` 后续必须以可审计 decision table 增加 card，而不是使用 tool name 启发式覆盖未知 output。 |
| `TodoRow`、`AskQuestionRow`、`WorkflowRunPanel` | todo summary、takeover 与 workflow 生命周期为各自插件/节点责任。 | T9.3 已承接 question takeover；T9.2/T9.5 仍须为 todo/workflow 建立专用 typed fixture。 |

## rc.2 可复现契约证据

在 Node `24.19.0` 与 pnpm `11.7.0` 上，于锁定官方工作树执行：

```text
pnpm exec vitest run packages/client/ui-tool/tests
```

结果为 **15 个文件、228 项测试全部通过**。其中包括 terminal（43）、read（21）、search（26）、diff（22）、todo（18）、ask-question（16）、web（15）、generic/keyed slot、row/type-chain、code subcalls、coverage tail 与 assembly surface 契约。[2]

这些测试共同锁定：未知 entryKey 必须回退到 `GenericToolCard`；已注册 renderer 以 keyed slot 获得 row；terminal/read/search/diff/web card 只能在对应 model 可判定时出现；running/failed/cancelled 不能被误示为 completed；todo 解析失败须回退通用摘要；details panel 对非结构化结果保留 flatten preformatted output。[2]

## 当前 native 边界与下一步

`NativeToolRow` 已保留同一 `ToolInvocation` 的完整 raw arguments 与 output，`NativeToolDetailsBody` 也以可复制 raw text 保持安全 fallback。该行为继续是 T9.1 的底线。T9.2 的下一生产步骤是先扩展可单测的 native row presentation，覆盖官方 search query-list summary、bash command/description 优先级、code body extraction、状态和 structured output decision；随后才增加 terminal/read/search/diff/todo/web 的 SwiftUI card。

当前 `ToolInvocation` 保留 `id`、`name`、`arguments`、`output`、`state`、`sequence` 与分离的 target-aware `callView`/`resultView`。只有 terminal adapter 对明确 admitted `card:'terminal'` 建立第一个 specialized path；在 Host 没有提供可验证的 structured view、card 不匹配或 target 错位时，native renderer 必须保持 raw fallback。read/search/diff/todo/web 专用 view 的 loading、failure、cancel、超长 output 性能、当前 rc.2 macOS paired visual/AX 工件和人工差异分类仍未完成，因此 **T9.2 保持未勾选**。

## 第二轮原生投影收敛（2026-08-22）

官方 `deriveBody` 在 empty args 时返回无 input section、在 non-JSON 中保留原始 payload、对 `run_code` 仅显示 `code` program、对其他可解析 JSON 显示 pretty JSON。[1] 原生将相同的 Foundation-only projection 提取为 `NativeToolRowPresentation`；`NativeToolRow` 在展开时只在 body 存在时显示 input，在 input 和 output 同时存在时才显示分隔线。此改动不依据 tool name 伪造 specialized result card，也不读取或执行 `ToolInvocation.view`。

`glass/ci/native-tool-row-presentation-portable-check.swift` 直接编译 production projection，并验证 query-list summary、bash description 优先级、URL 不升格为 file path、code program extraction、empty omission、malformed raw fallback 和完整 generic JSON body。该 harness 已接入 `portable-checks`。它是 Foundation-level 行为门禁；SwiftUI/AppKit typed XCTest 与 current-SHA macOS-26 paired visual/AX 仍是未完成的权威验证。

## 第三轮 terminal render-intent 收敛（2026-08-22）

rc.2 `terminalCardModel` 的选择不是 `bash`/`pwsh` 名称启发式：**running** 必须有 `callView.card == 'terminal'`；**settled** 必须有 `resultView.card == 'terminal'`。settled result 的 title 替换 pending call title，description 仅来自 call view；call head 被窗口截断时可使用 result title，但不得猜测 cwd。若 terminal call 收到 `card:'generic'` result（例如执行错误或后台启动），官方返回 `null` 并保留 generic raw body/output；non-zero exit code 或 signal 只在 settled terminal card 形成 terminal failure。[4]

原生 `ToolInvocation` 因此不再以单个可覆写 `view` 保存两侧 payload，而分别保留 `callView` 与 `resultView` 的完整 `ToolEventViewDTO`；event dispatcher 仅接受与 event type 相符的 `for:'call'` / `for:'result'`，错位 target 不会升级为 specialized card。`NativeToolTerminalViewAdapter` 只从类型严格的 `card/title/description/cwd/output/exitCode/signal` JSON 字段构造 Foundation-only terminal input；非整数 exit code 不被 coercion。`NativeTerminalCardPresentation` 保持在无 AppKit/SwiftUI 依赖的 `GlassCore/Session` source（避免改变锁定的 SwiftPM target graph），并由 Linux harness 直接编译以复刻官方上述 decision table；`NativeToolRow` 仅在其结果非空时显示原生 terminal body，否则保留既有完整 raw arguments/output generic fallback。

`native-tool-row-presentation-portable-check.swift` 现直接编译该 production decision model，并覆盖 running、result-title replacement、non-zero failure、terminal→generic result fallback、unknown running card 与 result-only window truncation；`NativeToolTerminalViewAdapterTests` 与 `NativeToolRowModelTests` 为 macOS XCTest 注册相同 typed 边界。Linux portable check 与 Swift syntax gate 已在本地通过，但不能替代本提交 current-SHA 的 macOS-26 编译、XCTest、runtime、长输出、取消、详情 decision、paired visual 或 AX 证据。read/search/diff/todo/web 专用 cards 和 `NativeToolDetailsBody` 的 terminal→read→diff→search→web / flattened `resultText` decision table仍未完成；因此 **T9.2 保持未勾选**。

## 第四轮 `resultText` 与 generic details 收敛（2026-08-22）

rc.2 `resultText` 逐一遍历 settled result `content`：`type:'text'` 的 text 原样加入，所有其他 block 各自 `JSON.stringify(block, null, 2)`，并以单个换行连接全部 part；**仅**当 content 为空且 error 同时具有 name/code 时，输出 `name: code`。这意味着 text-only concatenation 会吞掉 non-text block，而把整个 content array compact-encode 又会改变每个 block 的 JSON 层次与跨块分隔。[1]

原生 `NativeSessionStore` 现在把 result 逐项投影为 text 或单 block pretty JSON，保留 `ToolInvocation.errorName/errorCode`，并由 Foundation-only `NativeToolResultTextPresentation` 实现 join 与 complete-error fallback；既有 `NativeToolDetailsBody` 的 generic output 因而获得无损内容，而没有将未知 card 升级为专用 renderer。`NativeSessionStoreTests` 以实际 `session/event` call/result 路径锁定 text → reasoning → text 的顺序、空 result 的 `ToolError: interrupted` 与 published structured fields；portable harness 和 Core XCTest 另锁定纯模型。

`d07191d` 的 current-SHA portable-checks 曾失败，因为本轮最初将 helper 置于 `GlassPortableCore` 并使 `GlassCore` 新增依赖，违反项目的精确 target-graph gate。修复将 helper 保持在没有 AppKit/SwiftUI import 的 `GlassCore/Session` source，Linux workflow 继续以 `swiftc` 直接编译这些 production files；本地 target-graph self-test/gate、portable harness、Swift syntax、link 和 diff checks均通过。该修复仍须自己的 current-SHA macOS-26 编译/XCTest/visual/AX证据。

ToolDetails 的完整 native decision 尚未完成：terminal 已有 row card，但 details selector 仍须按官方严格次序 terminal → read → diff → search → web，只对对应 typed valid card 进入专用 body；running non-terminal 与所有未知/malformed/deferred card 继续保留 generic running/raw fallback。因此 **T9.2 和 T9.6 仍未勾选**。

## 第五轮 TerminalBlock 状态与 prompt 收敛（2026-08-22）

rc.2 `TerminalBlock` 将 running/done/error 的文字置为 StateDot 的无障碍 label，视觉本体是 dot；仅 signal 或 non-zero exit code 显示 error status pill。它把 cwd 缩为 home `~` 或最后一段，并将 multi-line command 渲染为逐行 prompt（第一行 cwd、后续 bare `$`）；settled clean command 不产生 status pill。[5]

原生 `NativeTerminalToolCardBody` 已改用 `NativeStateDot` 表达 ongoing/done/error，把 `terminal.running`/`terminal.done` 留给 accessibility label，且只在 signal/non-zero exit 时展示现有官方 locale 状态内容。它现在按最后路径段和逐行 command prompt 投影 call facts。仍未实现 ANSI span parsing、raw-output copy feedback、官方 16-line head/tail cap、no-wrap horizontal output scroll、home `~` resolution或 terminal full-height details body；因此这只减少已知状态/prompt差异，不能视为 T9.2 terminal renderer 完成或替代 current-SHA macOS visual/AX。

## 第六轮 TerminalBlock output/copy收敛（2026-08-22）

重新核对 rc.2 `TerminalBlock` 输出逻辑后，原生增加 `NativeTerminalOutputPresentation`：它保留原始 Host output作为复制内容，只去除一个trailing newline作为显示terminator，保留双newline产生的真实末行空白，并以显示line是否全为空白决定no-output；`NativeTerminalOutputWindow` 同样复刻head/tail规则。ToolRow明确传入无cap，ToolDetails传16而显示8/8与expand。官方copy绝不包含prompt/status，原生也只将`rawOutput`写入pasteboard。[5]

`NativeTerminalToolCardBody` 现以horizontal scroll的逐行output替换soft-wrap整段Text，加入官方copy/copy-success与terminal expand/collapse文案；whitespace/absent output进入官方no-output。`NativeToolTerminalViewAdapterTests`、portable harness与`NativeAccessibilityRuntimeTests.testTypedTerminalDetailsExportsCappedOutputAndCopy`分别覆盖raw/terminator/cap、Linux生产source和macOS AX seam。

ANSI parsed-span styling、control-only ANSI empty判定、clipboard success/refusal运行态、终端status pill视觉、当前SHA macOS编译/XCTest/runtime、paired visual与人工差异分类仍未完成。因而T9.2继续未勾选，不能以local Foundation/parse证据替代权威macOS工件。

## 第七轮 ANSI spans 与control-safe output 收敛（2026-08-22）

rc.2 `ui-primitives/src/ansi.ts` 在完整raw output上先剥离OSC、non-CSI escape和inert C0 controls，再让SGR state跨line延续并按span渲染；TerminalBlock以**parsed**行判定terminator和visible empty，因此`line\\nESC[0m`不生成假空行，只有真正的double newline留下末行空白。它对CR/backspace/erase-in-line执行terminal cell replay后才交给ANSI parser，且将basic ANSI颜色映射到官方label/state token，256/truecolor保留literal RGB。[6]

原生`NativeTerminalANSIPresentation`现成为唯一raw-control decoder：它构造Foundation-only SGR span（basic/256/truecolor、bold/dim/italic/underline/strike/hidden）、跨line fold、剥离OSC/non-CSI/inert controls，并在CR/backspace/CSI K出现时标记`requiresCursorReplay`，控制字节绝不进入SwiftUI `Text`。`NativeTerminalOutputPresentation`改为完整raw一次解析、按parsed末line去terminator、以span判定visible empty；typed ANSI head/tail window与原8/16窗口计数一致，copy仍使用未改写raw Host output。`NativeTerminalToolCardBody`已将visible spans用于逐行水平terminal output，basic color使用已登记官方semantic token，palette/truecolor为Host terminal data保留literal RGB；macOS AX seam断言可见`red`/`plain`而不泄露ESC。

`NativeTerminalANSIPresentationTests`及`native-terminal-ansi-presentation-portable-check.swift`覆盖SGR跨行、closer、OSC/C0清理、真实空行、palette/truecolor、hidden与cursor-replay标记；harness已接入portable checks。**尚未**复刻rc.2的CR/backspace/erase terminal-cell replay、wide-character/tab cursor语义或其视觉fixture；这些输入当前安全显示已清理的文本而不自称终端重绘等价，T9.2仍需要该缺口、current-SHA macOS compile/XCTest/runtime、paired visual和人工差异分类关闭。[6]
