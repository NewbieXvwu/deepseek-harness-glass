# T9.2 常用 Tool Renderer：rc.2 当前来源审计

**官方基线：** `deepseek-ai/deepseek-harness@b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`（dsh-v0.1.1-rc.2）。

> 本文记录官方实现和可复现的上游契约结果。它不替代本项目 current-SHA 的 macOS-26 编译、XCTest、运行态、视觉、键盘或无障碍证据。

## 官方 renderer 分层

官方 `tool-call-model.ts` 将冻结的 running/settled tool call 投影为稳定 row model。它负责 variant、title、summary、可打开的 file path、展开输入 body、flattened output、error summary 与状态；各专用 card 不能各自重新猜测同一份 payload。[1]

| 官方层 | 责任 | 原生实现约束 |
|---|---|---|
| `tool-call-model.ts` | `bash`、`read`、`search`、`write`、`edit`、`code`、`others` 分类；summary key 优先级；非 JSON raw fallback；running/stopped/error/ok 状态。 | `NativeToolRowModel` 必须从同一 typed invocation 派生摘要，未知 tool 保留 tool name 与 raw payload，不得以假定专用视图吞掉内容。 |
| `TerminalBlock`、`ReadBlock`、`SearchBlock`、`DiffBlock` | 展示已判定的 terminal/read/search/diff 内容。 | 专用 SwiftUI card 只能由明确 typed presentation decision 接管；未匹配时退回 generic raw body/output。 |
| `ToolRow`、`ToolCallTree`、`tool.call.toolview` | keyed row seat、whole-row expand 和 plugin-specific renderer registration。 | 原生 selection/expand 必须保持 keyed invocation identity；专用 renderer 不得破坏 generic fallback。 |
| `ToolDetails` | terminal → read → diff → search → web 的详情 card 选择；running 仅显示官方 details-running；其余 settled output 显示 flattened raw result。 | `NativeToolDetailsBody` 后续必须以可审计 decision table 增加 card，而不是使用 tool name 启发式覆盖未知 output。 |
| `TodoRow`、`AskQuestionRow`、`WorkflowRunPanel` | todo summary、takeover 与 workflow 生命周期为各自插件/节点责任。 | T9.3 已承接 question takeover；T9.2/T9.5 仍须为 todo/workflow 建立专用 typed fixture。 |

## rc.2 可复现契约证据

在 Node `24.19.0` 与 pnpm `11.7.0` 上，于锁定官方工作树执行：

```text
pnpm exec vitest run packages/client/ui-tool/tests
```

结果为 **15 个文件、228 项测试全部通过**。其中包括 terminal（43）、read（21）、search（26）、diff（22）、todo（18）、ask-question（16）、web（15）、generic/keyed slot、row/type-chain、code subcalls、coverage tail 与 assembly surface 契约。[2]

这些测试共同锁定：未知 entryKey 必须回退到 `GenericToolCard`；已注册 renderer 以 keyed slot 获得 row；terminal/read/search/diff/web card 只能在对应 model 可判定时出现；running/failed/cancelled 不能被误示为 completed；todo 解析失败须回退通用摘要；details panel 对非结构化结果保留 flatten preformatted output。[2]

## 当前 native 边界与下一步

`NativeToolRow` 已保留同一 `ToolInvocation` 的完整 raw arguments 与 output，`NativeToolDetailsBody` 也以可复制 raw text 保持安全 fallback。该行为继续是 T9.1 的底线。T9.2 的下一生产步骤是先扩展可单测的 native row presentation，覆盖官方 search query-list summary、bash command/description 优先级、code body extraction、状态和 structured output decision；随后才增加 terminal/read/search/diff/todo/web 的 SwiftUI card。

当前 `ToolInvocation` 保留 `id`、`name`、`arguments`、`output`、`state`、`sequence` 与分离的 target-aware `callView`/`resultView`。只有 terminal adapter 对明确 admitted `card:'terminal'` 建立第一个 specialized path；在 Host 没有提供可验证的 structured view、card 不匹配或 target 错位时，native renderer 必须保持 raw fallback。read/search/diff/todo/web 专用 view 的 loading、failure、cancel、超长 output 性能、当前 rc.2 macOS paired visual/AX 工件和人工差异分类仍未完成，因此 **T9.2 保持未勾选**。

## 第二轮原生投影收敛（2026-08-22）

官方 `deriveBody` 在 empty args 时返回无 input section、在 non-JSON 中保留原始 payload、对 `run_code` 仅显示 `code` program、对其他可解析 JSON 显示 pretty JSON。[1] 原生将相同的 Foundation-only projection 提取为 `NativeToolRowPresentation`；`NativeToolRow` 在展开时只在 body 存在时显示 input，在 input 和 output 同时存在时才显示分隔线。此改动不依据 tool name 伪造 specialized result card，也不读取或执行 `ToolInvocation.view`。

`glass/ci/native-tool-row-presentation-portable-check.swift` 直接编译 production projection，并验证 query-list summary、bash description 优先级、URL 不升格为 file path、code program extraction、empty omission、malformed raw fallback 和完整 generic JSON body。该 harness 已接入 `portable-checks`。它是 Foundation-level 行为门禁；SwiftUI/AppKit typed XCTest 与 current-SHA macOS-26 paired visual/AX 仍是未完成的权威验证。

## 第三轮 terminal render-intent 收敛（2026-08-22）

rc.2 `terminalCardModel` 的选择不是 `bash`/`pwsh` 名称启发式：**running** 必须有 `callView.card == 'terminal'`；**settled** 必须有 `resultView.card == 'terminal'`。settled result 的 title 替换 pending call title，description 仅来自 call view；call head 被窗口截断时可使用 result title，但不得猜测 cwd。若 terminal call 收到 `card:'generic'` result（例如执行错误或后台启动），官方返回 `null` 并保留 generic raw body/output；non-zero exit code 或 signal 只在 settled terminal card 形成 terminal failure。[4]

原生 `ToolInvocation` 因此不再以单个可覆写 `view` 保存两侧 payload，而分别保留 `callView` 与 `resultView` 的完整 `ToolEventViewDTO`；event dispatcher 仅接受与 event type 相符的 `for:'call'` / `for:'result'`，错位 target 不会升级为 specialized card。`NativeToolTerminalViewAdapter` 只从类型严格的 `card/title/description/cwd/output/exitCode/signal` JSON 字段构造 Foundation-only terminal input；非整数 exit code 不被 coercion。`NativeTerminalCardPresentation` 在 `GlassPortableCore` 复刻官方上述 decision table，`NativeToolRow` 仅在其结果非空时显示原生 terminal body，否则保留既有完整 raw arguments/output generic fallback。

`native-tool-row-presentation-portable-check.swift` 现直接编译该 production decision model，并覆盖 running、result-title replacement、non-zero failure、terminal→generic result fallback、unknown running card 与 result-only window truncation；`NativeToolTerminalViewAdapterTests` 与 `NativeToolRowModelTests` 为 macOS XCTest 注册相同 typed 边界。Linux portable check 与 Swift syntax gate 已在本地通过，但不能替代本提交 current-SHA 的 macOS-26 编译、XCTest、runtime、长输出、取消、详情 decision、paired visual 或 AX 证据。read/search/diff/todo/web 专用 cards 和 `NativeToolDetailsBody` 的 terminal→read→diff→search→web / flattened `resultText` decision table仍未完成；因此 **T9.2 保持未勾选**。
