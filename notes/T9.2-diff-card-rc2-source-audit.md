# T9.2 Diff Card：rc.2 来源审计

**官方基线：** `deepseek-ai/deepseek-harness@b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`（`dsh-v0.1.1-rc.2`）。

## Typed admission 与 call/result authority

`diffCardModel` 不以 tool name 选择卡。running call 只有在 `callView.card == 'diff'` 且 `diffs` 通过逐 hunk narrow 时呈现 intended diff；
settled call 则只接受 `resultView.
card == 'diff'`，result 的 applied diff 覆盖 call-time diff，并且即使 transcript window 丢失 call head 也能独立呈现。
settled generic/error、unknown tag、missing or malformed `diffs` 必须返回 null，保留 raw generic output。[1]

每一 hunk 需要 string `path`、`oldText` 为 string 或 null、以及 string `newText`。
空 diffs 不构成 diff card。card title 被明确丢弃，row 的现有 Edit/Write path summary 胜过 Host view title。
[1]

| 状态 | 权威 view | 专用 body | 未通过 admission 时 |
|---|---|---|---|
| running write/edit | typed call diff | intended diff | generic input/running path |
| settled write/edit | typed result diff | applied diff（替换 call diff） | flattened raw result/error |
| result-only window | typed result diff | applied diff | 不要求 call head |
| unknown/malformed/generic | none | 不渲染 diff card | safe raw generic fallback |

## Primitive rendering矩阵

`DiffBlock` 将 hunks 扁平为 path、delete、add 与 same-path gap rows；单个 trailing newline 是 terminator 而非额外行，interior blank line保留。
footer 以 distinct path 计文件数，并统计全部 old/new content line 的 removed/added totals。
row 使用 16-line 默认 cap；
ToolRow 使用更紧的 8-line cap。
body完全 no-wrap、横向滚动；删除和增加既以 `- `/`+ ` 前缀传达语义，也使用官方 error/success token。copy 输出为读取者看见的 path/gap/prefixed lines，而非原始 JSON。[2] [3]

## Native尚未实现边界

截至本审计，native 已有 typed terminal/read renderer，但没有 diff adapter、row/details card、hunk flatten、footer/copy/cap或negative fixtures。
下一增量必须先建立 Foundation-only typed `NativeToolDiffView`/projection，并明确保持 running call versus settled result authority，之后才可接入 SwiftUI。
因此 **T9.2 保持未勾选**。

## Foundation projection 与负向回归（2026-08-22）

本轮新增 `NativeToolDiffViewAdapter`，只承认 `card:'diff'`、非空 array `diffs`，且每一 hunk 都有 string path、**显式** null|string oldText 与 string newText；
oldText缺失、数值、generic/unknown card 或空 array均返回 nil。
`NativeDiffCardPresentation` 显式以 running call-side / settled result-side 选择源，并记录 `.call`/`.result` 以防后续 renderer 重新混合两侧。

`NativeDiffRowsPresentation` 复刻 hunk flatten：single trailing newline截断、interior blank 保留、same-path gap `⋯`、distinct files与全部 added/removed
counts。



portable harness和Core XCTest同时覆盖 call/result replacement、result-only fallback、terminator/interior blank/gap/count和malformed负例；
本地syntax与diff check通过。

这些Foundation证据不等于native DiffBlock已经呈现。
SwiftUI仍需从受控官方文字/token导入 copy/expand/footer，row 8/details 16 cap、no-wrap horizontal body与AX/visual current-SHA evidence；
在此之前generic fallback继续是未知 payload的唯一显示路径。

## Native DiffBlock row/details 接入（2026-08-22）
