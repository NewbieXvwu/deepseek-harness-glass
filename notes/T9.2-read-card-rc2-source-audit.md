# T9.2 Read Card：rc.2 来源审计

**官方基线：** `deepseek-ai/deepseek-harness@b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`（`dsh-v0.1.1-rc.2`）。

> 本文记录本轮 read card 的官方代码契约。任何 native 实现仍必须由自身 current-SHA macOS-26 编译、XCTest、运行态、paired visual 和 AX 证据验证。

## Admission 与状态矩阵

`readCardModel` 是 **result-side only**。
running read 没有 result view，必定返回 null 并在 row/details 保持 generic running；只有 settled result 的 `resultView.card == 'read'` 才可产生 read card。
generic/unknown/non-read result，以及 read 工具自身 error/non-envelope result，都必须回退 raw generic output，而不是因为 tool name 为 `read` 就猜测文件内容。[1]

| 官方状态 | row | details Output | 原生实现约束 |
|---|---|---|---|
| running read | path summary + running state，无 read card | `details.running` | 不得从 call args 伪造 read lines。 |
| settled typed read | compact read card（8-line cap） | full read card（primitive default 16-line cap），
保留 Input JSON | 仅在 card schema 完整、类型正确时进入专用 body。
|
| read error/generic result | error/stopped row，无 read card | flattened raw result | card admission不能覆盖 Host错误。 |
| unknown/malformed card | generic | raw generic result | fail closed。 |

## Typed read result fields

官方 model 从 result view 复制 `{ number, text }` lines；
其 label 先使用 result replacement `title`，否则将 `path` 按 session cwd 相对化并再按 Host home 缩为 `~`。`totalLines` 与可选 `lang` 直接传给 primitive；
running 不读取 call-side read data。[1]

`ReadBlock` 显示 code-surface banner（label/lang/window count/copy），按源文件自己的 1-based line number 绘制 gutter，
保留单行 source 的 `white-space: pre` 与横向滚动。


默认 cap 为 16；chat row 使用独立 8-line cap。
超过 cap 时 head/tail 展示并由 expand/collapse 操作切换；copy 仅复制 raw window lines（不复制 gutter），空 window 不显示 copy。[2] [3]

## 已知 native 边界

截至本审计，native 只保留 `ToolInvocation.resultView` raw JSON 与 generic raw arguments/output。
尚未有 read-card adapter、line validation、cwd/home label resolution、row 8-line / details 16-line cap、copy、syntax highlight、line
gutter、head-tail 或 no-wrap horizontal scroll。



实现必须先建立 Foundation-only typed adapter与 negative fixtures，再接入 SwiftUI；任何未验证字段仍保留 generic fallback。因此 **T9.2 保持未勾选**。

## Foundation projection 与窗口回归（2026-08-22）

本轮新增 `NativeToolReadViewAdapter`，只接受 result JSON 中类型正确的 `card:'read'`、`path`、整数 `totalLines`、每项均为正整数 `number` 与 string `text` 的 `lines`；
card tag、fractional/negative line number、缺失字段或 `totalLines < lines.
count` 任一不满足即返回 nil。
`NativeReadCardPresentation` 还要求 completed 状态，令 running read、unknown card 和 malformed data fail closed 到现有 raw generic fallback。

`NativeReadCardWindowPresentation` 单独锁定 rc.
2 head/tail 算法：20 行在 chat cap 8 时为 1–4 + 17–20（hidden 12），在 details cap 16 时为 1–8 + 13–20（hidden 4），expanded 回复全量。
portable harness、Core XCTest seam、Swift syntax、target-graph self-test/gate、links 与 diff check 在本地通过。

ReadBlock 的 banner count、copy、expand/collapse 与 associated AX 文案目前不在本地官方 locale catalog 的可用 key 中；为了遵守不自创文案约束，本轮不提前挂载不完整 SwiftUI ReadBlock。
后续必须先从受控官方来源扩展文案/asset input，再把 typed presentation 接到 row 8-line 与 details 16-line body，并由 current-SHA macOS-26 visual/AX验证。

## ReadBlock syntax highlight admission（2026-08-22）

rc.
2 `ReadBlock`不逐行tokenize：它先将当前显示window的全部raw line text以换行连接，整段交给`highlightLines(raw, lang)`，因而多行comment/string保留grammar上下文；
再把返回的二维runs按源行索引与gutter一一配对。
`lang`未知、缺失或lazy grammar尚未加载时，`highlightLines`返回`undefined`，每行直接显示plain source；
grammar异步就绪后订阅触发重渲染。它的颜色来自Shiki `css-variables` theme的`--shiki-*` token，不是ReadBlock自定色值。[2] [4]

当前native Read card仅安全承认Host typed `lang`并将其作为banner事实；仓库没有受审计的Shiki/tokenizer bridge，也没有官方`--shiki-*`到SwiftUI颜色的等价主题输入。
为避免把路径扩展名、Host lang或自造关键字色错误提升为官方highlight，`NativeReadToolCardBody`继续渲染plain source。
后续高亮接入必须同时带入完整window context、registered/lazy grammar admission、per-line token alignment以及可回链的token-color主题，不能逐行正则模拟。[4]

尚无本次提交的 macOS current-SHA compile/XCTest/runtime、copy feedback行为、expanded state reset、syntax highlight、cwd/home label缩略、paired
visual或人工差异分类证据。



因此该 read body仍不能关闭T9.2。
